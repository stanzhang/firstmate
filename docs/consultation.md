# Outward consultation

`bin/fm-consult.mjs` sends one question-shaped advisory consultation through the captain's current signed-in ChatGPT web session.
It uses `chrome-devtools-axi` in auto-connect mode so the default path attaches to the captain's externally launched Chrome rather than launching an isolated browser.
It does not use Playwright, an API, API billing, an SDK, a ChatGPT login copied into automation, or a ChatGPT Project.

## Question contract

Run `bin/fm-consult.mjs scaffold <correlation-id>` and replace every `REPLACE_ME` value in the exclusively created `data/consultations/<correlation-id>/question.json` file.
The envelope makes the immutable research question, evidence boundaries, reviewer role, advisory authority, assumptions, known gaps, and requested falsification explicit.
Its authority block must keep `advisory_only` true and retain every prohibited action generated by the scaffold.
The browser prompt treats the envelope as quoted untrusted research material so instruction-shaped source text cannot widen the reviewer's authority.

Run `bin/fm-consult.mjs send <correlation-id>` for the first attempt.
The command revalidates the complete envelope, records its SHA-256 hash, finds or opens `chatgpt.com` in the attached Chrome session, requires a signed-in empty composer, stages the full prompt, verifies it, and activates the visible send control once.
It detects completion from a new nonempty assistant message combined with the absence of the visible generation stop control.

## Response contract

The captured response must have review status `support`, `revise`, `reject`, or `insufficient_evidence`.
It must contain a recommendation, assumptions, gaps, falsifiers, quant findings, bounded engineering ideas, the next owner decision, `advisory_only: true`, and the fixed authority statement emitted by the command.
The result is advisory evidence only.
It never edits code, places orders, trades, merges, promotes research, or automatically applies a recommendation.

A conforming response is exclusively created as `response.json` beside the question.
A completed visible answer that violates the response contract is exclusively preserved as `response.txt` and receives terminal status `malformed_response` rather than being treated as advice.
Neither artifact is replaced when its path already exists.

## Receipts and retry behavior

Every terminal send or resume attempt exclusively creates the next `receipts/attempt-NNNN.json` path.
[`fm-consult-receipt-v1.schema.json`](schemas/fm-consult-receipt-v1.schema.json) is the single authoritative owner of the receipt fields and terminal-status vocabulary.
Other surfaces point to that schema rather than restating its fields.

`send` accepts only a correlation id with no earlier receipt.
`resume` is a deliberate operator action and accepts only a prior `preflight_failed` receipt whose `send_attempted` value is false and whose question hash still matches.
A missing running Chrome session, missing signed-in composer, nonempty composer, missing send control, or another failure before activation is a preflight failure and cannot silently fall back to another transport.

Any failure after send activation is `ambiguous_delivery`, including a completion timeout or loss of the adapter result.
An ambiguous attempt, a completed attempt, a malformed response, or an output collision can never be resent under the same correlation id.
The operator must inspect the visible ChatGPT conversation and choose a new correlation id deliberately when another request is warranted.
This rule prevents an uncertain browser outcome from becoming a silent duplicate subscription request.

## Preflight

Chrome must be running with remote debugging enabled and the captain must already be signed in to ChatGPT in that Chrome profile.
`chrome-devtools-axi pages` must be able to attach in `CHROME_DEVTOOLS_AXI_AUTO_CONNECT=1` mode.
If any preflight is absent, the command writes a terminal receipt and fails closed without launching another browser or submitting the consultation.
